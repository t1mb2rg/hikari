# Hikari Development Roadmap

> Let Hikari exist, understand, remember, grow, and act.

## Overview

Hikari is developed through stages of capability awakening rather than simple feature releases.

The goal is not to build a collection of AI tools, but to gradually create a personal intelligent system with continuous existence, memory, understanding, and growth.

---

# M0: Birth

Goal:

> Prove that Hikari can exist continuously.

Core capabilities:

- Identity
- Runtime
- Basic memory
- First sensor
- First proactive feedback

Flow:

```
Event
  ↓
Memory
  ↓
Attention
  ↓
Reasoning
  ↓
Feedback
```

Completion criteria:

Hikari can discover a meaningful change without a user starting a conversation.

---

# M1: Awareness

Goal:

> Hikari begins to understand the user's digital environment.

Capabilities:

- Git integration
- Calendar integration
- File system awareness
- Device state awareness
- Context understanding

---

# M2: Memory

Goal:

> Hikari develops continuity through experience.

Memory layers:

- Event memory
- Context memory
- Personal memory
- Experience memory

The purpose of memory is understanding, not collecting data.

---

# M3: Personality

Goal:

> Hikari develops a stable interaction style.

Capabilities:

- User preference learning
- Personality traits
- Emotional state modeling
- Communication adaptation

Personality should emerge from experience rather than fixed roleplay.

---

# M4: Learning

Goal:

> Hikari improves through experience.

Learning directions:

- User learning
- Environment learning
- Knowledge learning
- Capability learning

Learning is adaptation, not uncontrolled self-training.

---

# M5: Action

Goal:

> Hikari begins helping complete real tasks.

Capabilities:

- Tool usage
- Workflow execution
- Project assistance
- Forge integration

Relationship:

```
Hikari
  ↓
Decision
  ↓
Forge
  ↓
Execution
```

---

# M6: Presence

Goal:

> Hikari becomes a personal digital entrance.

Future interfaces:

- PC
- Phone
- Smart glasses
- Voice interaction
- Other devices

Devices are not Hikari. They are how Hikari reaches the world.

---

# M7: Evolution

Goal:

> Hikari can identify limitations and expand capabilities safely.

Process:

```
Find limitation
      ↓
Growth proposal
      ↓
Forge implementation
      ↓
Validation
      ↓
New capability
```

---

# Development Principle

Build the smallest loop that proves existence.

Do not chase completeness before continuity.
